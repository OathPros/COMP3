Browsing
========

Browsing typically works in conjunction with lists or grids of content, where opening an item switches to a dedicated view for that item. It offers an alternative to opening content items in individual windows, which is smoother and less disruptive.

Using a grid to present a grid of videos, each of which opens in its own view, is one example.

Browsing can be combined with sidebars and views switchers, to provide navigation with a particular sections of an app.

Guidelines
----------

* Avoid deep navigation paths. Generally speaking, browsing should only have one level of depth.
* Update the header bar to reflect the current view:
   * Show a heading for the view.
   * Replace the primary with a secondary menu.
* If search is provided, it should remain available irrespective of the view that is displayed.
* Support the standard keyboard shortcuts for browsing: *Alt+←* and *Alt+→* to move forward and back.
* When in a sub-view, a back button should be shown at the start of the header bar (in left-to-right locales, on the far left).
